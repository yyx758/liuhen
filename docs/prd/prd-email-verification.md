# PRD：邮箱验证与邮箱找回密码（SMTP 发信）

## 1. 背景

下一阶段要做提醒推送，渠道为**页面内通知 + 邮件**。邮件提醒的前提是：系统知道一个**真实、属于该用户**的邮箱，并且能发出邮件。

现状（多用户阶段，见 `prd-multi-user.md` D4、D14）：

- 注册时邮箱可选，只做格式和唯一性校验，不验证归属。
- 个人设置里可以修改或清空邮箱，只需当前密码。
- 系统没有任何发信能力。
- 忘记密码只能联系管理员重置为临时密码（多用户 D4、5.5）。

本阶段解决"邮箱可信 + 能发信 + 用邮箱自助找回密码"，提醒本身是下一阶段。

## 2. 目标

1. 接入 SMTP 发信（作者的 QQ 邮箱作为发件人），配置只来自环境变量 / `.env`。
2. 注册必须填写邮箱，并通过 6 位邮件验证码证明邮箱归属；之后照旧进入管理员审核。
3. 个人设置里绑定或修改邮箱也必须通过验证码；清空邮箱不需要验证码。
4. 记录邮箱是否已验证（`users.email_verified_at`），供下一阶段判断"能不能发邮件提醒"。
5. 忘记密码时，用户可以通过**已验证邮箱**收取验证码并设置新密码；管理员重置保留为兜底。

## 3. 不做

- 邮件提醒本身、通知中心（下一阶段）。
- 强制老账号绑定邮箱：老账号照常使用，未验证邮箱的用户以后只收页面内通知。
- 发信队列、重试、退信处理。验证码是同步发送，失败直接告诉用户。
- 验证链接、短信。

## 4. 决策

| 编号 | 问题 | 决定 |
| --- | --- | --- |
| E1 | 验证形式 | 6 位数字验证码，邮件发送，表单里填写后一起提交 |
| E2 | 与审核的关系 | 先验证再审核：验证码通过才能提交注册，账号仍是 `pending` |
| E3 | 老账号 | 不强制；在个人设置里绑定/修改邮箱时走验证码。迁移后所有已有邮箱都视为**未验证** |
| E4 | 有效期与次数 | 验证码 10 分钟有效；同一个验证码最多输错 5 次，之后作废，需要重新获取 |
| E5 | 发送频率 | 同一邮箱 60 秒内只能获取一次；同一邮箱每小时最多 5 次；同一 IP 每小时最多 10 次 |
| E6 | 新码与旧码 | 同一邮箱同一用途重新获取后，旧验证码立即作废 |
| E7 | 存储 | 只存验证码的 SHA-256，不存明文；验证成功后标记已使用，不可重复使用 |
| E8 | 发信失败 | 同步发送；SMTP 失败返回 502 "验证码邮件发送失败，请稍后再试"，这次生成的验证码不保存（不能让用户拿到一个"已发送"的假象） |
| E9 | 未配置 SMTP | 发送验证码接口返回 503 "邮件服务未配置"；注册因此无法完成。本地开发需要在 `.env` 配置 SMTP |
| E10 | 命令行创建管理员 | `--email` 仍可选，写入的邮箱为未验证状态，可登录后在个人设置里验证 |
| E11 | 邮箱是否已被占用（注册、改邮箱） | 注册用途获取验证码时，若邮箱已被其他账号使用，直接返回 409 "邮箱已被使用"（与注册接口现有行为一致，PRD 多用户 5.1 已接受注册接口暴露占用情况） |
| E12 | 谁能用邮箱找回密码 | 只有邮箱**已验证**且状态为 `active` 的账号。未验证邮箱的老账号仍找管理员重置，或先登录到个人设置验证邮箱 |
| E13 | 找回密码不暴露账号 | 获取找回验证码的接口**对任何格式正确的邮箱都返回同样的成功响应**；只有满足 E12 时才真的发信。冷却和每小时上限命中时也静默不发，而不是返回 429（否则"第二次请求被限流"就说明这个邮箱有账号）。同一 IP 的限流照常返回 429，它与邮箱无关。提交新密码时，邮箱不存在和验证码错误返回同一个错误 |
| E14 | 找回成功后 | 更新密码哈希、清除"强制改密"、**吊销该账号全部会话**、清除该账号（用户名和邮箱两个登录键）的登录失败锁定；写 `password_reset` 账号事件，`actor` 为本人，`details.source = "email"`。不自动登录，用户用新密码重新登录 |

## 5. 功能说明

### 5.1 获取注册验证码

- 公开接口，输入邮箱。
- 邮箱规范化规则同现有（去空格、转小写、格式校验）。
- 依次检查：格式 → 是否已被占用（E11）→ 频率（E5）→ 生成验证码、作废旧码（E6）→ 发信（E8）→ 保存。
- 成功返回 `{ "expires_in": 600, "resend_after": 60 }`，前端据此做倒计时。

### 5.2 注册

- 字段：用户名、密码、邮箱（**必填**）、验证码（**必填**）。
- 在同一个事务里：校验验证码（存在、未过期、未使用、未超次数、邮箱和用途匹配）→ 创建用户（`email_verified_at` = 当前时间）→ 标记验证码已使用 → 写 `user_registered` 账号事件（`details` 增加 `email_verified: true`）。
- 验证码错误：返回 400 "验证码错误或已过期"，并给该验证码计一次失败；第 5 次失败后作废。
- 其余校验（用户名、密码、唯一性、IP 限流）不变。

### 5.3 个人设置：绑定或修改邮箱

- 先获取验证码：登录后接口，输入新邮箱和当前密码。密码错误 → 400；新邮箱与当前邮箱相同 → 422 "新邮箱与当前邮箱相同"；被他人占用 → 409。
- 再提交修改：`PATCH /auth/me` 带 `email`、`code`、`current_password`。成功后 `email` 更新、`email_verified_at` = 当前时间，写 `email_changed` 事件（`details` 增加 `verified: true`）。
- 清空邮箱：`email` 为空时不需要 `code`，`email_verified_at` 同时清空。
- 验证码绑定到"用户 + 邮箱"：A 用户获取的验证码不能被 B 用户使用。

### 5.4 邮箱找回密码

1. 登录页"忘记密码"进入找回页，输入邮箱，点"获取验证码"。
2. 后端规范化邮箱（格式错误 → 422），然后按 E12 / E13 处理：符合条件且未触发频率限制时发信；其余情况什么都不做。两种情况都返回 `{ "expires_in": 600, "resend_after": 60 }`。
3. 用户填写验证码和新密码（新密码规则同注册，前端再确认一次）提交。
4. 后端在一个事务里：按邮箱找到符合 E12 的账号 → 校验该账号的找回验证码 → 校验新密码 → 按 E14 更新。
   - 邮箱没有对应账号、账号不符合 E12、验证码错误或过期：都返回 400 "验证码错误或已过期"。验证码错误时照常计失败次数。
   - 新密码不符合规则：422，验证码**不**消耗，用户改好密码后可以继续用。
5. 成功返回 204，页面提示"密码已重置，请使用新密码登录"。

已知的暴露面：SMTP 故障时（502 / 503）只有真实存在的账号会走到发信这一步，所以故障期间能分辨出邮箱是否有账号。为此加一层队列不值得，接受。

### 5.5 邮件内容

- 发件人显示名：小记（品牌名，沿用多用户 D13）。
- 标题：`【小记】邮箱验证码`。
- 正文：纯文本，包含验证码、用途（注册 / 绑定邮箱 / 找回密码）、有效期 10 分钟、"如果不是你本人操作，请忽略本邮件"。找回密码的邮件额外提示"如果不是你本人操作，你的密码不会被修改"。

### 5.6 用户信息

- `GET /auth/me` 与管理后台用户列表增加 `email_verified: bool`。
- 个人设置页在邮箱后显示"已验证" / "未验证"。

## 6. 接口

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/auth/register/email-code` | 公开 | `{email}` → 发送注册验证码 |
| POST | `/auth/register` | 公开 | 新增必填 `email`、`code` |
| POST | `/auth/me/email-code` | 登录 | `{email, current_password}` → 发送绑定验证码 |
| PATCH | `/auth/me` | 登录 | 新增 `code`（设置邮箱时必填，清空时忽略） |
| POST | `/auth/password-reset/email-code` | 公开 | `{email}` → 按 E12 / E13 发送找回验证码，始终返回同样的成功响应 |
| POST | `/auth/password-reset` | 公开 | `{email, code, new_password}` → 重置密码，返回 204 |

## 7. 数据

### 7.1 `users` 新增列

- `email_verified_at`（timestamptz，可空）。迁移时全部为空（E3）。
- 约束：`email IS NOT NULL OR email_verified_at IS NULL`。

### 7.2 新表 `email_verification_codes`

| 列 | 说明 |
| --- | --- |
| `id` | 主键 |
| `purpose` | `register` / `change_email` / `reset_password` |
| `email` | 规范化后的邮箱 |
| `user_id` | `change_email`、`reset_password` 时为对应用户，`register` 时为空 |
| `code_hash` | 验证码 SHA-256 |
| `failed_attempts` | 输错次数 |
| `created_at`、`expires_at` | UTC 时间 |
| `used_at` | 验证成功、被使用的时间 |
| `invalidated_at` | 作废时间（被新码替换或输错 5 次） |
| `ip` | 请求 IP |

- 约束：`purpose IN (...)`；`purpose = 'register'` 时 `user_id IS NULL`，否则 `user_id IS NOT NULL`。
- 索引：`(email, purpose, created_at)`，用于取最新码与频率统计。
- `user_id` 外键：删除账号（只有 pending / rejected 可删）时一并删除其验证码记录。
- 过期记录不做定时清理（量很小）；如需清理，留到后续阶段。

## 8. 配置

| 变量（`.env` / 部署环境变量） | 说明 |
| --- | --- |
| `smtp_host` / `LIUHEN_SMTP_HOST` | QQ 邮箱为 `smtp.qq.com` |
| `smtp_port` / `LIUHEN_SMTP_PORT` | 默认 `465`（SSL） |
| `smtp_username` / `LIUHEN_SMTP_USERNAME` | 完整 QQ 邮箱地址，同时作为发件地址 |
| `smtp_password` / `LIUHEN_SMTP_PASSWORD` | QQ 邮箱的 **SMTP 授权码**（在 QQ 邮箱"设置 → 账号"开启 SMTP 服务后生成），不是 QQ 密码 |

- 授权码只放在 `.env`（本地）或 `deploy/secrets/`（线上），不提交、不写进文档示例、不在对话里传递。
- 连接与发送超时 10 秒。

## 9. 前端

- 注册页：邮箱改为必填；邮箱输入框右侧增加"获取验证码"按钮，成功后 60 秒倒计时；新增"验证码"输入框。发送失败时显示后端返回的原因。
- 个人设置：修改邮箱弹窗改为两步：填写新邮箱和当前密码 → 获取验证码 → 填写验证码 → 保存。清空邮箱仍然一步完成。邮箱后显示验证状态。
- 管理后台：用户列表邮箱旁显示是否已验证。
- 登录页"忘记密码"改为跳转找回页 `/forgot-password`（新增，公开）：邮箱 + 获取验证码 → 验证码 + 新密码 + 确认新密码 → 提交。页面上注明"只有已验证的邮箱能找回密码；未验证邮箱请联系管理员重置"。版式沿用注册页。

## 10. 验收

- 后端测试覆盖：发码成功/各类失败、频率限制、旧码作废、过期、输错 5 次作废、验证码不可复用、验证码不能跨邮箱/跨用途/跨用户使用、SMTP 失败不保存验证码、未配置返回 503、找回密码只对已验证且正常的账号发信、找回接口对有无账号的响应一致（含频率限制）、找回成功后旧密码失效且所有会话下线且登录锁定解除、新密码不合规时验证码不消耗、注册与改邮箱后 `email_verified` 为真、清空邮箱后为假、迁移前后结构一致。
- 测试不连接真实 SMTP，替换发信函数并检查收件人与正文。
- 作者在本地 `.env` 配置 QQ 邮箱授权码后，手动走一遍注册，确认能收到邮件。
