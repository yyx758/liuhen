# PRD：任务提醒（页面内通知 + 邮件）

## 1. 背景

任务有开始时间 `start_at` 和截止时间 `due_at`，但系统从不主动提醒，用户只能自己打开页面看。上一阶段（`prd-email-verification.md`）已经具备 SMTP 发信能力，并记录了邮箱是否已验证（`users.email_verified_at`），本阶段在此基础上实现提醒。

## 2. 目标

1. 每个任务可以设置"提前多久提醒"，到点后生成**页面内通知**，并在条件满足时发送**提醒邮件**。
2. Agent 创建任务时可以顺带设置提醒；修改提醒与修改其他字段一样只生成提案。
3. 提醒可靠：服务重启不丢、不重复发送、任务改期或删除后旧提醒自动作废。
4. 用户可以在个人设置里关闭邮件提醒。

## 3. 不做

- SSE / WebSocket 实时推送：前端定时拉取未读通知（SSE 在路线图里单独推进）。
- 一个任务多个提醒、重复提醒（每天 / 每周）、"稍后提醒"（snooze）。
- 通用偏好管理：只加一个"邮件提醒"开关，不做通用的偏好框架。
- 浏览器系统通知（Web Notification / Web Push）、短信、微信。
- 每个用户自定义默认提醒时间。

## 4. 决策

| 编号 | 问题 | 决定 |
| --- | --- | --- |
| R1 | 触发方式 | 后台循环**定时轮询数据库**，与现有 `expiry_loop` 同样的结构（`asyncio` 循环 + `asyncio.to_thread` 执行同步数据库操作）。不引入消息队列、Celery、APScheduler。数据库是提醒状态的唯一来源，进程内存不保存任何提醒状态 |
| R2 | 轮询间隔 | 30 秒；提醒的实际送达时间最多晚 30 秒左右（邮件另加发送耗时） |
| R3 | 提醒时间 | 任务新增 `remind_before_minutes`（可空）。为空表示不提醒；0 表示准时提醒。基准时间：有 `start_at` 用 `start_at`，否则用 `due_at`。提醒时间 = 基准时间 − 提前分钟数 |
| R4 | 可选范围 | 0–10080（7 天）任意整数。页面提供预设：不提醒 / 准时 / 5 分钟 / 15 分钟 / 30 分钟 / 1 小时 / 1 天；Agent 可以设置预设以外的值（如"提前 2 小时" = 120），页面照常显示 |
| R5 | 默认值 | 新建任务默认**不提醒**，避免每个任务都发邮件 |
| R6 | 提醒时间已过 | 设置时如果算出的提醒时间已过、但基准时间还没到（如 10 分钟后开始的任务设"提前 30 分钟"），下一轮轮询立即提醒；基准时间本身已过，不生成提醒（页面显示"任务时间已过，不会提醒"） |
| R7 | 任务变化 | 改期、修改提前时间、删除、标记完成：在**同一事务里**作废待触发的提醒，并按新状态重新生成（已完成或已删除的任务不再生成）。完成后又改回未完成，按 R6 重新生成 |
| R8 | 错过的提醒 | 到点后 **1 小时内**照常发页面通知和邮件；超过 1 小时（如服务停机）只生成一条"已错过"的页面通知，不发邮件 |
| R9 | 邮件条件 | 同时满足才发：邮箱已验证、"邮件提醒"开关开启、不是"已错过"。发送前再检查一次这些条件（触发和发送之间用户可能关了开关） |
| R10 | 邮件可靠性 | **至少一次**：发送成功但来不及标记时，下次会重发（偶尔重复一封），而不是漏发。失败自动重试，最多 3 次；到点超过 1 小时仍未发出则放弃并记为失败 |
| R11 | 邮件开关 | 个人设置里一个总开关，默认开启 |
| R12 | Agent | 创建任务工具增加可选的提醒参数；修改提醒走修改提案（需要用户确认），与其他字段规则一致。Agent 不能确认提案、不能直接改提醒 |
| R13 | "提醒我"的理解 | 用户说"提醒我……"并给出时间、但没说提前多久时，按**准时提醒**（0）处理；用户只是要求创建任务、没有提到提醒时，不设置提醒。用户说了提前多久，按用户说的设置 |
| R14 | 留痕 | 提醒设置是任务字段，随任务的创建、修改、删除事件写入审计（`operation_events` 的前后快照里自然包含）。提醒触发不写 `operation_events`，通知本身就是记录。**本阶段不做邮件发送的留痕**：`notifications` 上的邮件状态列只用于重试和防重，不在留痕页、通知列表里展示，以后需要时再做 |

## 5. 功能说明

### 5.1 设置提醒

- 页面：任务弹窗（新建 / 编辑）增加"提醒"下拉框，选项见 R4；任务列表、日历里有提醒的任务显示一个小标记。
- 手动修改仍走 `PATCH /tasks/{id}`（带 `If-Match`），`remind_before_minutes` 是可修改字段之一。
- 修改时间或提醒后，后端按 R6 / R7 重新计算。前端根据基准时间自行判断并提示"任务时间已过，不会提醒"，后端不在任务响应里返回提醒的触发状态（`TaskRead` 同时用作提案和审计快照，不放派生字段）。

### 5.2 Agent

- `create_task` 工具参数增加可选的 `remind_before_minutes`，说明按 R13 写进工具描述和系统提示词。
- `propose_update` 的 `changes` 增加 `remind_before_minutes`，作为独立的一组（与标题、优先级一样单独确认）。
- 回复里说明实际设置的提醒（如"已创建，开始前 30 分钟提醒你"）；未设置提醒时不提。
- 测评增加场景 27–30：显式提前时间、"提醒我"无提前时间（R13）、修改提醒走提案、取消提醒走提案；已有的创建场景 01、02、08 增加"没有擅自设置提醒"的检查（未提提醒）。提醒时间已过（R6）是后端计算规则，由后端测试覆盖，不放进 Agent 测评。

### 5.3 触发（后台循环每 30 秒）

1. 取出到点的待触发提醒（`remind_at <= 当前时间`，状态 `pending`），用 `FOR UPDATE SKIP LOCKED` 加锁，每轮最多 100 条。
2. 对每条：到点不超过 1 小时 → 生成提醒通知；超过 → 生成"已错过"通知（R8）。按 R9 决定邮件状态（待发送 / 不需要）。
3. 提醒标为 `fired` 或 `missed`。以上在**一个事务**里完成：要么通知生成且提醒标记，要么都没发生，不会重复生成。

### 5.4 发送邮件（同一个后台循环，紧接触发之后）

1. 取出邮件状态为"待发送"、到了重试时间的通知，加锁并**先提交一个小事务**：状态改为"发送中"，记录开始时间、尝试次数 +1。
2. 在事务外发邮件（SMTP 可能耗时 10 秒，不能拿着数据库行锁等待）。发送前按 R9 再检查一次；不再满足则记为"已跳过"。
3. 成功 → "已发送"；失败 → 回到"待发送"并设置下次重试时间（1 分钟、5 分钟后），第 3 次失败或到点超过 1 小时 → "失败"，记录最后一次错误。
4. 恢复：状态为"发送中"超过 5 分钟（进程在发送途中崩溃），视为发送结果未知，改回"待发送"重试——这就是 R10 的"至少一次"。

邮件内容：

- 标题：`【小记】提醒：<任务标题>`
- 正文：任务标题、开始时间或截止时间（UTC+08:00）、"可以在小记里查看或关闭提醒"。纯文本，与验证码邮件同一个发件人。

### 5.5 页面内通知

- 顶部导航增加通知入口（铃铛 + 未读数角标）。前端每 30 秒拉取一次未读数，切回页面时立即拉取一次。
- 点开显示最近通知列表：任务标题、任务时间、"已错过"标记；点击跳到对应任务（任务已删除则提示）。
- 单条标为已读、全部标为已读。通知不能删除。
- 通知里保存任务标题的快照，任务改名或删除后通知内容不变。

### 5.6 个人设置

- 增加"邮件提醒"开关。邮箱未验证时开关旁提示"验证邮箱后才能收到提醒邮件"。

## 6. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST / PATCH | `/tasks`、`/tasks/{id}` | 请求和响应增加 `remind_before_minutes`（`PATCH` 传 `null` 表示取消提醒） |
| GET | `/notifications` | 当前用户的通知，新的在前，分页（`before_id`、`limit`） |
| GET | `/notifications/unread-count` | 未读数（角标用） |
| POST | `/notifications/{id}/read` | 标为已读（重复调用幂等） |
| POST | `/notifications/read-all` | 全部标为已读 |
| PATCH | `/auth/me/preferences` | `{email_reminders: bool}` |

`/auth/me` 增加 `email_reminders`。所有新接口依赖 `CurrentUserId`，按 `user_id` 隔离，别人的通知 ID 返回 404。

## 7. 数据

### 7.1 `tasks` 新增列

- `remind_before_minutes`（int，可空），约束 `BETWEEN 0 AND 10080`。

### 7.2 新表 `task_reminders`（提醒的触发状态）

| 列 | 说明 |
| --- | --- |
| `id` | 主键 |
| `user_id` | 所属用户 |
| `task_id` | 任务；任务删除时一并删除（`ON DELETE CASCADE`），通知里已有快照 |
| `remind_at` | 应提醒时间（timestamptz） |
| `status` | `pending` / `fired` / `missed` / `cancelled` |
| `created_at`、`finished_at` | 生成时间；触发、错过或作废的时间 |

- 部分唯一索引：同一任务最多一条 `pending`。
- 索引：`(status, remind_at)`，供轮询使用。
- 任务改期时不修改旧行，而是把旧的 `pending` 改为 `cancelled` 并插入新行：每条提醒的生命周期单向，便于排查"为什么提醒了 / 为什么没提醒"。

### 7.3 新表 `notifications`

| 列 | 说明 |
| --- | --- |
| `id` | 主键 |
| `user_id` | 所属用户 |
| `kind` | `reminder` / `missed` |
| `task_id` | 任务 ID（不加外键，任务删除后保留） |
| `reminder_id` | 来源提醒（不加外键，同上） |
| `task_title`、`task_time` | 快照：任务标题、基准时间 |
| `created_at`、`read_at` | 生成时间；已读时间 |
| `email_status` | `not_needed` / `pending` / `sending` / `sent` / `skipped` / `failed` |
| `email_attempts`、`email_next_attempt_at`、`email_sent_at`、`email_error` | 邮件重试与结果 |

- 索引：`(user_id, id)` 供列表，`(user_id) WHERE read_at IS NULL` 供未读数，`(email_status, email_next_attempt_at)` 供发送。

### 7.4 `users` 新增列

- `email_reminders`（bool，非空，默认 `true`）。

## 8. 前端

- 任务弹窗增加"提醒"下拉框；任务行和日历块上有提醒的显示小标记（视觉沿用原型的标签样式）。
- 顶部导航增加通知入口和下拉列表，样式沿用原型的弹层和标签；原型没有通知界面，按现有导航和弹层的视觉扩展，不新增风格。
- 个人设置增加"邮件提醒"开关。

## 9. 验收

- 后端测试（固定时钟，直接调用"轮询一轮"的函数，不真的等待）：
  - 提醒时间计算（start_at 优先、准时、已过但基准未到、基准已过）。
  - 改期 / 改提前时间 / 删除 / 完成 / 重新打开后，待触发提醒正确作废与重建；确认修改提案后同样生效。
  - 到点生成通知且只生成一次；并发两轮不重复（`SKIP LOCKED`）；超过 1 小时记为错过且不发邮件。
  - 邮件：条件不满足不发；发送前条件变化记为跳过；失败重试与放弃；"发送中"超时恢复后重发。
  - 通知接口的分页、未读数、已读幂等与用户隔离。
